# 0008. Dark-first design system on shadcn/ui, Radix and D3

Status: Accepted · 2026-10-27

## Context

The product's value is in its visualizations, and as a portfolio piece it should show a coherent visual system rather than the default look of a component library. Charts need many distinct, legible colors and a few chart types that libraries do not cover well (network graph, bump chart, tile map).

## Decision

- A dark-first design system: quiet near-black surfaces, a mint accent, eight vibrant categorical chart colors, a sequential ramp for heatmaps and maps, a diverging ramp for values around a median. A light theme exists and stays flat.
- Fonts: Space Grotesk for titles, IBM Plex Sans for text, IBM Plex Mono for every number.
- The source of truth is the "Job Market Radar" design system made in Claude (tokens, component guidelines, previews). Its tokens are exported to `packages/ui/src/tokens.css` as CSS variables.
- Components: shadcn/ui on Radix primitives, styled through Tailwind reading the same CSS variables.
- Charts: D3 (or visx where a React wrapper helps). Every chart reuses shared `ChartFrame`, `Legend` and `ChartTooltip` components so they look and behave the same.
- Tables: TanStack Table with TanStack Virtual for long lists.

## Alternatives considered

- **MUI, Mantine or Chakra.** Faster start, but hard to escape their visual identity.
- **Recharts, Chart.js or ECharts.** Quick for standard charts, limiting for custom interactions and network graphs.
- **Light-first theme.** Common and safe, but the vibrant palette reads best on dark surfaces.

## Consequences

- We own the component code (shadcn/ui copies components into the repo) and maintain it.
- Every text color meets 4.5:1 contrast on its surfaces in both themes, and status never relies on color alone (▲ ▼ glyphs, words).
- Tokens can drift between the design system and the code. For now `tokens.css` is regenerated by hand when the design system changes; automate it if it becomes a chore.
